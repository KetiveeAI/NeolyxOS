Kernel

AreaStateWhat the code shows
UEFI loader, bootRealBoots to the desktop in QEMU/OVMF. The desktop is loaded from \EFI\BOOT\desktop.elf (kernel/src/core/boot_image.c).
ProcessesPartialPer-process address spaces; spawn, exec, fork, wait, exit. No threads.
SchedulerPartialRound-robin; the timer preempts ring 3 only, kernel code is not preemptible. One CPU, no SMP.
Memory syscallsPartialOnly brk is registered. mmap/munmap are declared in syscall.h but are not in syscall_table.def, so they return ENOSYS.
Shared memoryPartialHandles (handle.close 140, handle.dup 149) and shm.create/shm.map/shm.unmap (141 to 143) per docs/desktop/proposals/kernel-shm-ipc.md, mapped in a per-process shared region at 0x4000_0000_0000. Pages are zeroed, returned to the PMM when the last handle and mapping go, and released on exit, kill, fault and exec. Verified by tests/userland/shmtest. Handles cross processes over channels (see IPC).
IPCWorkingChannels (chan.create/chan.send/chan.recv 144 to 146), obj.wait (147) and named ports (port.listen/port.connect/port.accept 150 to 152) per docs/desktop/proposals/kernel-shm-ipc.md; ABI 1.1 with NX_ABI_FLAG_IPC. Messages of up to 1 KiB carry up to 4 handles; sends never block; nx.* port names are reserved for system processes. Verified by tests/userland/ipc_test (two processes share a 4 MiB buffer, the client crashes, all memory returns). No pipes; PTY syscalls 60 to 67 are declared in syscall.h but not registered.
File descriptorsPartialPer process: 16 descriptors in each PCB (fd_table), kept across exec, closed when the process exits, is killed or faults. Socket numbers are still one global table in the network stack, shared by every process. Verified by tests/userland/fdtest.
Framebuffer syscallsPartialfb.map gives any user process the raw framebuffer. fb.flip copies the full frame. fb.flip_rects (148, ABI 1.2) copies only given rectangles and is limited to system processes; the desktop does not use it yet (week 3, step 3). Verified by tests/userland/fbtest and tests/host/nx_fb_clip_test.c. No vsync.
Input syscallsPartialOne global event queue: the first process to poll takes each event. input.register is a no-op.
Syscall dispatch, ABI query, filter, auditRealnx_syscall.c, syscall_table.def.
Boot log and diagnosticsRealAll kernel log output is kept in a 64 KiB ring (kernel/src/video/bootlog.c). A kernel exception or panic draws the last lines on screen. With \EFI\BOOT\diagnose.flg on the boot volume the loader shows firmware facts, the kernel shows its log and a boot summary on screen, and every disk driver refuses writes (write_guard.c). Hardware test procedure: docs/hardware/smoke-test.md. Host test tests/host/bootlog_test.c.

AreaStateWhat the code shows
PS/2 keyboard and mouseRealIRQ1 and IRQ12, press/release event queue. The controller is detected first (ps2_controller_present); without one the kernel logs that the machine has no input.

The driver leaves a controller alone when the firmware still owns it, its registers are above 4 GB, or it needs scratchpad buffers (the QEMU q35 xHCI is above 4 GB, so it is left alone). Graphics and desktop

AreaStateWhat the code shows
Desktop shellRealOne userspace process (desktop/) draws everything with NXCanvas on the CPU: menu bar, dock, windows, overlays. Frames are damage-driven: an idle desktop draws only the clock and menu bar once a second (about 5 of every 300 ticks), a client window's commit redraws only its damaged rectangles, and the screen is updated with fb.flip_rects; any shell activity still redraws the whole screen. A debug build (make EXTRA_CFLAGS=-DDESKTOP_DAMAGE_VERIFY) checks every frame against a full redraw. Its heap (desktop/lib/nx_malloc.c) reuses and merges freed blocks and the panel cache is capped at 16 MiB, so memory stays flat across app launches (host test tests/host/nx_malloc_test.c).
Shell-hosted appsRealSettings, Path, Shell, Task Manager, Fonts and Setup are views inside the desktop process (desktop/shell/views/).
Window managerReal, single processWindows, z-order, snap, Overview, Stage, switcher, all inside the desktop process. App windows from other processes are ordinary shell windows (same decorations, tiling, minimize, Overview).
nxrender (gui/nxrender_c)Not usedAbout 12k lines. desktop/shell/nxrender_bridge.c has empty draw functions. nxserver_compositor.c is a sketch and is not used: the window server was built inside the desktop instead (desktop/shell/nxserver). gpu_driver.c reports a fake GPU and needs hosted libc.
Out-of-process GUI appsPartialThe desktop's window server (desktop/shell/nxserver) listens on port nx.display and speaks window protocol 1.0 (sdk/nxwindow/nxwin_proto.h, spec docs/desktop/proposals/nxserver-window-protocol.md): a separate process opens a window, draws into shared memory that the server maps read-only and draws without a copy, and gets keys, pointer, CONFIGURE and CLOSE_REQUEST. Verified by tests/userland/wintest (hostile cases, crash cleanup, a live window) and tests/host/nxw_check_test.c. Commits redraw only their damaged rectangles (host test tests/host/nxs_damage_test.c). Apps use libnxwindow (sdk/nxwindow/nxwindow.h, spec docs/desktop/proposals/libnxwindow.md) instead of the raw protocol: connect, windows, one buffer per window with the FRAME_DONE rule enforced, events; verified by tests/host/nxwindow_test.c and tests/userland/nxwtest. NxUI (REOX) apps run in their own window through libnxwindow (nxui_run; verified by tests/userland/nxuitest: clicks, keys, resize and close); Calculator.app still needs a build with reoxc and a QEMU check. The built-in apps still run inside the desktop (week 5).
GPU accelerationMissinggpu.c and nxgfx_accel.c are CPU loops.
Vulkan (lib/vulkan)MissingFuture work.
